# Living town: สัตว์ อากาศ และตกปลา

- Server สร้างสัตว์ 13 ตัว: แมว 3, กระต่าย 3, ผีเสื้อ 3, ผึ้ง 2, เต่าทอง 2
- เดิน/บินรอบจุดบ้าน หยุดพัก สุ่มจุดใหม่ และไม่เดินผ่านน้ำ น้ำพุ ตัวบ้าน หรือต้นไม้
- ตำแหน่ง/การพักของสัตว์ซิงก์ผ่าน Colyseus; การกระพือปีก/กระโดดเป็น cosmetic ฝั่ง client
- อากาศในห้องเดียวกันตรงกัน เปลี่ยน sunny → rain → snow ทุก 120 วินาที
- ฝนมีแสงมืดลงและวงกระเพื่อมบ่อ; หิมะมีเกล็ดลอย; แดดมีแสงอุ่น
- จำกัดอนุภาคตามขนาดจอ (55 บนมือถือ, 95 บน desktop) และ update สัตว์ 10 Hz

## วิธีตกปลา

เดินใกล้ **ด้านใดก็ได้รอบริมบ่อ** ไม่เกิน 48px จากฝั่ง (ห้ามยืนในน้ำ) หรือกด “ไปบ่อตกปลา” เพื่อเดินอ้อมไปท่าเรือ
กดเริ่มตกปลาหรือ Space รอ 4–8 วินาที เมื่อปลาติดเบ็ด เกจจะแสดงตัวชี้วิ่งซ้าย–ขวา
กด Space หรือปุ่มดึงเบ็ดบนมือถือเมื่อตัวชี้ตรงแถบแดงกลางเกจ (35%–65%) ภายใน 8 วินาที
ตัวชี้หนึ่งรอบไปกลับใช้ 2.4 วินาที กดได้ครั้งเดียว: กดนอกแถบแดง กดก่อนปลากิน หรือปล่อยหมดเวลาจะปลาหลุด
เก็บเบ็ดหรือเดินออกเพื่อยกเลิก ป้ายเดิมเป็นจุดช่วยหา ไม่ใช่ข้อจำกัดตำแหน่งตกปลา
Space ไม่รบกวนการพิมพ์แชทหรือชื่อตัวละคร

ปลา 4 ชนิดพร้อมขนาดสุ่ม เซิร์ฟเวอร์เป็นผู้ตัดสินและบันทึกกระเป๋าปลา
จับสำเร็จแต่ละตัวได้รับ **ชิปฟรีสุ่ม 1–20 ชิปทันที** เข้ากระเป๋าป๊อกเด้ง แม้ชิปเหลือ 0 ก็เริ่มตกปลาได้
น้ำหนักของรางวัล n ชิป = 21−n รวม 210: โอกาส n ชิป = (21−n)/210 × 100%
เช่น 1 ชิป 9.52%, 5 ชิป 7.62%, 10 ชิป 5.24%, 15 ชิป 2.86%, 20 ชิป 0.48%
ทุกจำนวนออกได้จริง และรางวัลที่มากขึ้นมีโอกาสลดลงเสมอ; ดูอัตราทั้ง 20 จำนวนในหน้าตกปลา
เซิร์ฟเวอร์ตรวจเวลารับคำสั่งกับเกจจริง สุ่มด้วย crypto.randomInt และเพิ่มชิปครั้งเดียวต่อ castId
ไม่ใช้ cursor/score/timestamp/rewardChips จาก client; กดก่อน/พลาด/ช้า/ยกเลิก/ส่งซ้ำไม่ได้ชิป
Client ปรับนาฬิกาด้วย RTT ของ fish:clock และวาดตัวชี้ทุก animation frame; ไม่เป็นผู้ตัดสินผลหรือรางวัล
ไม่มีเงินจริง ไม่ต้องขายปลาเอง จำนวนปลาและชิปจำตาม Guest UUID เดิมแม้รีเฟรช
แต่ยังเป็น memory-only หายเมื่อ server restart
โต๊ะป๊อกเด้งยังสำรองสูงสุด 5 เท่าของเดิมพัน: เดิมพันขั้นต่ำ 10 ต้องมี 50 ชิป จำนวนปลาที่ต้องจับขึ้นกับรางวัลสุ่ม

## API

| Client → Server | Payload |
| --- | --- |
| `nature:sync` | `{}` ขออากาศกับเวลา server |
| `fish:sync` | `{}` ขอสถานะเบ็ดและกระเป๋าปลา |
| `fish:cast` | `{}` server ตรวจพิกัดจริงรอบริมบ่อ, ไม่อยู่ casino, ไม่มีเบ็ดอีก connection |
| `fish:reel` | `{ castId }` server ตรวจผู้เล่น, connection เจ้าของ, รอบเบ็ด, จังหวะจริง |
| `fish:cancel` | `{}` เก็บเบ็ดของ connection นี้ |
| `fish:clock` | `{ nonce }` ส่ง nonce เดิมกับ serverTime กลับ เพื่อคำนวณ clock offset แบบ RTT midpoint |

Owner-only: `fish:state` มี phase, castId, location, biteStartedAt, deadline, serverTime, กระเป๋าและผล (รวม rewardChips)
location เป็นพิกัด bobber ในบ่อที่ได้จากมุมของตำแหน่งผู้เล่นจริง ไม่จำกัด spot ID
`wallet:update` ส่งยอดใหม่ทันทีเมื่อได้ปลา; client ไม่เป็นผู้กำหนดจำนวนรางวัล
ไม่ส่งเวลาปลาจะกินเหยื่อล่วงหน้า ข้อผิดพลาดผ่าน `api:error`
Public schema มีสถานะตกปลาและ fishingBobberX/fishingBobberY เพื่อให้คนอื่นเห็นเบ็ดและทุ่น แต่ไม่มี castId หรือ inventory
การเดิน เข้า casino หลุด หรือปิดแท็บยกเลิกเบ็ด; ปลาที่จับสำเร็จแล้วไม่ถูกลบ

## ทดสอบ

`cd server && npm test`: กติกาอากาศ สัตว์ collision เวลา/จังหวะ/สิทธิ์ตกปลา และ regression เดิม

ทดสอบสิทธิ์ผ่าน WebSocket จริงโดยเฉพาะ: `cd server && npx tsx --test test/nature-transport.test.ts`

- ผู้เล่นคนอื่นที่รู้ castId ก็สั่งดึงหรือยกเลิกเบ็ดเจ้าของไม่ได้ แม้ปลากินเหยื่อแล้ว
- ข้อมูล playerId/sessionId/owner ที่แอบใส่ใน payload ไม่แทนตัวตนของ connection ที่ผ่าน auth
- อีกแท็บของ Guest เดียวกันเห็นยอดปลา/ชิปของบัญชีร่วมกัน แต่ไม่เห็น castId และสั่งดึงเบ็ดของแท็บแรกไม่ได้
- castId ที่หายไป รูปแบบผิด ของอีกผู้เล่น หรือหมดอายุหลังกลับเข้าเกม ถูกปฏิเสธ
- เจ้าของได้ปลา 1 ตัวและชิปตามผลสุ่มของ server เท่านั้น แม้ส่ง total/rewardChips ปลอม; replay ไม่เพิ่มรางวัล
- ข้อความ private และ public schema ไม่เผย castId ของเจ้าของให้ผู้เล่นอื่น
- เดินไปด้านเหนือ/ตะวันตก/ใต้/ตะวันออกจริงผ่าน WebSocket แล้วตกปลาได้ครบทุกด้าน
- ปลอม cursor=.5, hit=true หรือตัวเลขเวลา ไม่ทำให้การกดนอกแถบแดงชนะ
- Unit tests ตรวจฝั่ง 72 มุม ขอบเกจ และสุ่มครบทั้ง 210 ผลเพื่อพิสูจน์อัตราทุกจำนวน

ชุดทดสอบเปิดเซิร์ฟเวอร์ชั่วคราวบน localhost/พอร์ตสุ่ม ไม่แตะเกม production หรือยอดชิปผู้เล่นจริง

Local browser QA:

1. `cd server && RO_WEATHER_PHASE_MS=5000 npm start` (เฉพาะ QA; production ใช้ default)
2. `cd client && npm run dev`
3. `cd client && npm run test:nature`

บน production: `E2E_URL=https://ro-lounge.vercel.app npm run test:nature`
ไม่เร่งอากาศหรือแก้เวลาใน client เพื่อให้ผ่านการทดสอบ
